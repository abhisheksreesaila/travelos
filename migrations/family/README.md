# Family database migrations

See docs/family-db.md. Files here are fh-saas `utils_migrate` migrations, `NNN_description.sql`, each with `-- UP --` and `-- DOWN --`.
They are applied to each family database the first time it is opened after a deploy. Migrations are applied lazily, when a family is first opened, which assumes one worker process (see docs/family-db.md "One worker"). `001_trip_timezone.sql` adds `trips.timezone` (F-057). `002_push_subscriptions.sql` adds the `push_subscriptions` table (F-066). `003_member_phone.sql` adds `members.phone` (F-069). `004_payment_backoff.sql` and `005_payment_next_try.sql` add `matrix_payments.attempts` and `next_try_at` (F-274, D-851; one statement a file). `006_payment_hotel_address.sql` and `007_payment_guests.sql` add `matrix_payments.hotel_address` and `guests`; `008_booking_email_sent.sql` and `009_booking_cancel_email_sent.sql` add `matrix_bookings.booked_email_at` and `cancel_email_at` (F-285, D-911, D-912). `010_booking_hotel_id.sql` adds `matrix_bookings.hotel_id` (F-288, D-935). The tables in
`gitaway/familydb.py` are the baseline and are made when a family database is first opened.
