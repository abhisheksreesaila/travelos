# fh-saas workarounds (propose these to the package)

- 2026-10-01 · F-039 · Tenant DB files are relative to the working directory (`_tenant_url_from_settings`, `_ensure_tenant_database` in db_tenant.py) and the host DB comes from `DB_NAME`. Workaround: `gitaway/auth.py` `configure_storage()` chdirs into `GITAWAY_DATA_DIR`, so code must never use relative paths. Package fix: an optional `DB_DIR` / `TENANT_DB_DIR` used by `_build_host_url` and `_tenant_url_from_settings`, storing absolute URLs.
- 2026-10-01 · F-039 · `handle_oauth_callback` always redirects to `/dashboard` (or `/admin/dashboard`) via `route_user_after_login`; an app cannot choose the landing page. Workaround: `/auth/callback` calls it, discards its redirect, and redirects to the `next` kept in the session. Package fix: an optional `redirect_to` argument (or a `post_login_url` hook) on `handle_oauth_callback` / `route_user_after_login`.
- 2026-10-01 · F-039 · No public "sign this user in" function: the OAuth callback inlines create_or_get_global_user + get_user_membership + provision_new_user + create_user_session, so a dev/test sign-in has to repeat those four calls (`gitaway/auth.py` `sign_in_dev`). Package fix: extract `complete_login(session, host_db, oauth_id, email, info) -> (global_user, membership)` from `handle_oauth_callback` and call it from there.
- 2026-10-01 · F-039 · `provision_new_user` names the tenant "<username>'s Workspace" and gives no way to name it (GitAway wants "<name>'s family"), and it always creates a new tenant: an invited email cannot join an existing family on first sign-in (ADR-0004, F-043). Package fix: optional `tenant_name` and a `join_tenant_id`/`role` argument, or a pre-provision hook that looks up pending invitations.
- 2026-10-01 · F-039 · `handle_logout` does `session.clear()` and redirects to `/login`. (F-040 retired this workaround: the cookie holds only the sign-in, so `/logout` is plain `handle_logout`.) It used to snapshot the non-auth keys and restore them. Package fix: a `keys` / `keep` option, or a `redirect_to`.
- 2026-10-01 · F-039 · `create_auth_beforeware` can only redirect when signed out, never "hydrate if present": an app with mostly public pages must skip nearly every path by regex (done with a negative lookahead in main.py). Package fix: `optional=True` that sets `request.state.user = None` instead of redirecting.
- 2026-10-01 · F-039 · `HostDatabase` is a process singleton built from the environment on first use; `HostDatabase.reset_instance()` exists (call `close()` first) but our tests just set `GITAWAY_DATA_DIR` before importing the app, one database per test session. `fh_saas.db_host.timestamp()` uses the deprecated `datetime.utcnow()` (hundreds of DeprecationWarnings in the suite).
- 2026-10-01 · F-040 · `HostDatabase` is one shared SQLAlchemy connection, and `verify_membership` / `get_user_membership` call `host_db.rollback()` and query on it, so concurrent requests (FastHTML runs sync routes in a threadpool) share one connection. Workaround: `familydb.family_db` takes a process lock around `require_tenant_access`. Package fix: open a short connection per call, or hold a lock inside `HostDatabase`.
- 2026-10-01 · F-040 · `get_user_membership` returns the first active membership with no ordering or choice, so a person in two families always lands in the same one (needed for F-043 invites and for the two-members tests, which switch the other membership off). Package fix: `get_user_membership(host_db, user_id, tenant_id=None)` and an ordering (most recently used), plus a way to switch tenants in the session.
- 2026-10-01 · F-040 · `utils_sql.upsert` on SQLite is `INSERT OR REPLACE`: it ignores `conflict_cols` and `update_cols` and replaces the whole row, so a partial record silently drops the other columns. Workaround: only `insert_only` and `update_record` (changed fields only) are used for rows two people can touch. Package fix: `INSERT ... ON CONFLICT (...) DO UPDATE SET ...` on SQLite 3.24+, as on PostgreSQL.
- 2026-10-01 · F-040 · `with_transaction` only commits or rolls back; it never starts a write transaction, so a read-then-write inside it can go stale (SQLite's default BEGIN is deferred). Workaround: every such write starts with a write statement (`familydb.lock`). Package fix: `with_transaction(db, immediate=True)` issuing `BEGIN IMMEDIATE` on SQLite.
- 2026-10-01 · F-040 · `get_or_create_tenant_db` gives no way to set `journal_mode=WAL` or a busy timeout for the tenant engines. Workaround: `ensure_schema` runs `PRAGMA journal_mode=WAL` once per family (it persists in the file); the busy timeout is pysqlite's default 5 s. Package fix: SQLite engine options in settings (`DB_SQLITE_WAL`, `DB_BUSY_TIMEOUT`).
- 2026-10-01 · F-040 · `utils_migrate` works on one database; there is no "apply to every tenant" runner, and `discover_migrations` logs a warning when the folder is missing. Workaround: families are migrated lazily the first time each is opened after a deploy (`familydb.ensure_schema`). `apply_migrations` also uses the deprecated `datetime.utcnow()` and `db.execute` (not `db.conn.execute`). Package fix: `migrate_all_tenants(host_db, migrations_dir, dry_run=True)`.
- 2026-10-01 · F-040 · `register_tables` / `register_table` only create missing tables; they never add a column to an existing one, so schema changes need a migration. Worth saying in the docs.
