- 2026-09-30 · Page CSS must load after tokens.css and base.css: build every page's <head> with `layout.styles(*extra)` (page() does). tests/test_shell.py checks every route, because a same-specificity rule in base.css silently beat page rules.
- 2026-09-30 · Developer worktrees can start on an old commit: every build brief must say "`git merge --ff-only master` first", and merges must check the combined tree, not just each branch.
- 2026-09-30 · Headless screenshots with --hide-scrollbars hid a sideways page scroll for two reviews: when verifying a page, also measure documentElement.scrollWidth vs clientWidth at 1440, 1280, 1000, 800, 390 and 320.
- 2026-09-30 · No text is cut off with an ellipsis in GitAway UI: labels wrap, shorten, or become icon + accessible name. Check headers and chips at 1280 and 1000, where columns are tightest. Exception: calendar blocks keep their true height (height is time); a short block fades its overflow and expands on hover/focus instead of growing.
- 2026-09-30 · Client-side state seeded at page load (e.g. which offer the split view opens) must follow later picks: test the "change it in the tiled view, then expand" path, not just a fresh page load. String-matching tests missed this in F-025.
- 2026-09-30 · Assert a price or total on its own element (e.g. `id="ws-total"`), never as a substring of the whole page: embedded data made `"$2,308" in html` pass for the wrong pick in F-015.
- 2026-09-30 · GitAway was built too large: the captain needed 75% browser zoom to see a full screen. Design and verify at 1440×900 and 1280×800 at 100% zoom: the main content of every screen must fit without scrolling.
- 2026-09-30 · Sizes are rem off one root (12px desktop and tablet, 16px phone; tokens.css). Never write px for a size; breakpoints scale too (a layout that switched at 1100 switches at 825). tests/test_scale.py enforces it.
- 2026-09-30 · Parallel workers collided on port 5002 and one killed another's browser: each worker brief names its own server port and browser debug port, and workers stop only processes they started (by PID, never by pattern).
- 2026-09-30 · Parallel workers overwrote each other's helper scripts in the shared scratchpad: each worker keeps its scripts in its own scratchpad subfolder named after its ticket (e.g. scratchpad/f031/).
- 2026-10-01 · The session cookie holds only the sign-in (F-040, F-041 retired the budget code and its tests): anything a family plans goes in a family table (`familydb.FAMILY_TABLES`, `docs/family-db.md`), written as one short transaction on its own rows. Never read a whole JSON blob, change it and write it back: two members editing at once lose data. Model tests use `person()` and the family database, not a session dict with made-up keys.
- 2026-09-30 · F-028 was built backwards (phone panes kept instead of hidden), with a test that locked in the wrong behaviour. Quote each acceptance check word for word in the build brief, and test layout rules like "only this pane shows" in the browser (tests_browser/), not with CSS-text checks.
- 2026-10-01 · Writes are gated centrally (`gitaway/access.py`: every non-GET needs the editor role unless its path is listed open or admin-only), and `tests/test_roles.py` walks every POST route as a viewer. A new write route needs no gate of its own, but a new open route must be added to both lists on purpose. Memberships and invites live in the host database, which `tests/wipe.py` clears of invites and non-owner memberships: give every invited person a unique address in a test.
- 2026-10-01 · YAML parsing silently changed confirmation numbers (012345 → 5349, yes → True) and dropped repeated keys. Parse user-pasted YAML with raw scalars (no int/bool/float typing) for text fields and refuse duplicate keys with a line number.
- 2026-10-01 · The captain found phone option B (plain day strip + cards) "bland": phone screens need a strong focal card (e.g. a dark "Up next" card), clear hierarchy and colour, not a flat list.
- 2026-10-01 · The import preview's "Change something" posted back to the preview route, so it did nothing, and no test pressed it. Every button on a new screen gets a test that presses it and checks where it lands; an "edit" path must reach an editable form.
- 2026-10-02 · Screenshot runs left ~260 headless Chromium processes and ~15 GB of browser profiles in /tmp, which crashed browser tests and filled the disk quota (sqlite "disk I/O error"). Agents must close the browsers they start and delete their throwaway profile and data folders when done; prefer Playwright's own launch (it cleans up) over a hand-started Chromium.
- 2026-10-02 · Putting real Google keys in the project's .env made the dev sign-in vanish in every test run, including worktrees (fh-saas's load_dotenv walks up and finds the main checkout's .env, and fills only keys that are missing). Tests pin such keys to "" before importing the app rather than removing them.
- 2026-10-03 · A merge that stopped on a conflict was followed by `git commit -am` in the same command chain, which committed the conflict markers into master. Never chain commits after a merge with `;`; check `git status` for unmerged files before any commit.
- 2026-10-03 · A test that faked a missing module with `monkeypatch.delitem(sys.modules, ...)` let the next import create a second copy of the module, so later tests patched one copy while the app used the other (random-order failures). Fake a missing module with `monkeypatch.setitem(sys.modules, name, None)`; tests/conftest.py also restores gitaway.geo after every test.
- 2026-10-04 · FastHTML fills route parameters named like request headers or objects (`origin` became the Origin header, `session`, `auth`, `request`, `data`...): never name a form field `origin`; a browser test caught it where the TestClient route test, which posts fine, did not. Browser-test every new form.
- 2026-10-04 · F-066 was merged with a "mark done" message but the plan still said [doing]: the status edit was lost while merging master in. After a merge that should change a ticket's status, grep docs/plan.md for that ticket before calling it done.
- 2026-10-05 · The project now also runs on a Windows VM. There `python` is the Microsoft Store stub (it hangs): always `pixi run python`. Text files are read as UTF-8 only because pixi.toml sets PYTHONUTF8=1; parametrize ids must stay short (Windows caps PYTEST_CURRENT_TEST at 32767 characters); a test cannot delete a SQLite file it still has open, so give throwaway copies their own folder.
- 2026-10-05 · On this Windows VM, Git Bash `sed` inserts (`i\`/`a\` with `\` line breaks) and regex escapes (`\?`, `\d`) in sed replacements silently collapse lines or drop backslashes: a test was saved as one line (all comment) and checked nothing. Write multi-line code and regexes with the Edit tool or a heredoc file, then run the new test once with the fix removed to see it fail.
- 2026-10-05 · The captain judges GitAway on his iPhone as an app, not a website: every change is touch-first (hold, drag, double-tap, in place; no forms or dropdowns for what a finger can do), minimal (fewest buttons, quiet filters), and every screen change animates briefly and smoothly (never a stop-and-go full page flash). Design and test new screens against that bar.
- 2026-10-06 · Sarvam speech-to-text (REST) refuses audio over 30 seconds ("use the batch API"): any recording longer than that is cut into standalone pieces on the page (a new MediaRecorder on the same stream every ~25 s) and transcribed piece by piece. Check a provider's real limits with a live call before building on its docs.
- 2026-10-06 · gitaway.* loggers need their own handler (main.py configure_gitaway_logging); fh-saas configure_logging only covers fh_saas, so logger.info from gitaway.ask never reached railway logs.
- 2026-10-06 · The captain wants one "liquid" motion everywhere (the F-106 plan card: it grows out of what was tapped with a soft spring and folds back into it). Every new sheet, menu, popover, toast or screen change uses the shared motion tokens and helper (F-109), never its own timing; reduced motion turns it into a short fade.
- 2026-10-06 · An agent ran `taskkill /IM python.exe`, killing every Python process on the shared Windows VM (other agents' tests and the server included). Never kill by image name or pattern: stop only the PIDs you started (record them when you start them).
- Arrivals use the calm ease (`--motion-ease`), never `--motion-out`: that is the fold's ease-in, and a glide on it crawls, then jumps (F-113). On the iPhone, prefer one compositor animation (translate/scale/opacity via `MO.run`) over per-frame JS for anything small.
