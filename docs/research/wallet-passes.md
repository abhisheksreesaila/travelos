# Wallet passes (F-288, D-931..D-935)

Read 2026-11-17 from the vendors' own pages. "Confirmed" = the page text said it. "Unconfirmed" = the page would not load as text (Apple's developer.apple.com/documentation is JavaScript only), so the value is from the ticket or the archived guide and must be checked once with a real certificate on an iPhone.

## Apple Wallet (PassKit)
- Package: a ZIP of pass.json, images, `manifest.json` and `signature` at the archive root, no wrapper folder, no .DS_Store. [Creating the pass](https://developer.apple.com/library/archive/documentation/UserExperience/Conceptual/PassKit_PG/Creating.html) (confirmed)
- `manifest.json`: a dictionary of every file (except manifest.json and signature), key = path in the package, value = hex SHA-1 of the file. (confirmed)
- `signature`: a detached PKCS #7 signature of manifest.json, signed with the Pass Type ID certificate's private key, the Apple WWDR intermediate certificate included, with the S/MIME signing-time attribute. The pass's `passTypeIdentifier` must match the certificate and `teamIdentifier` its Team ID. (confirmed) WWDR: [Apple Certificate Authority](https://www.apple.com/certificateauthority/).
- Images: `icon.png` 29x29 pt (@2x, @3x too; Wallet refuses a pass without an icon, unconfirmed on the page), `logo.png` up to 160x50, `thumbnail.png` 90x90, `strip.png`, `background.png`, `footer.png`. Same guide (sizes confirmed).
- pass.json keys ([PassKit Package Format Reference](https://developer.apple.com/library/archive/documentation/UserExperience/Reference/PassKit_Bundle/Chapters/TopLevel.html), unconfirmed text): `formatVersion` 1, `passTypeIdentifier`, `serialNumber`, `teamIdentifier`, `organizationName`, `description`, one style key (`generic` or `eventTicket`, each with header/primary/secondary/auxiliary/back fields), `barcodes` [{format PKBarcodeFormatQR, message, messageEncoding iso-8859-1, altText}], `relevantDate` (W3C date-time with a time zone offset), `locations` [{latitude, longitude, relevantText}] (at most 10, per the ticket; unconfirmed), `backgroundColor`/`foregroundColor`/`labelColor` as `rgb(r,g,b)`. `webServiceURL` + `authenticationToken` are only for passes that update: we send neither (a pass is a snapshot).
- Style choice: `generic` for a hotel stay (eventTicket draws a ticket notch and a date line meant for events).
- MIME type: `application/vnd.apple.pkpass`, extension `.pkpass` (unconfirmed on the page, universally documented; Safari on iOS opens it in Wallet).
- Badge: the "Add to Apple Wallet" artwork is licensed only after the Developer Program member accepts the [Apple Wallet Marketing Artwork License](https://developer.apple.com/wallet/add-to-apple-wallet-guidelines/) (no own versions, no changes, near the pass, a line for other devices to open it on an iPhone). Decision D-932: text buttons until the founder accepts it.

## Google Wallet
- Needs an issuer account ([Business Console](https://pay.google.com/business/console)), a service account with a JSON key, the Google Wallet API enabled, and the service account added as a user of the issuer. [Prerequisites](https://developers.google.com/wallet/generic/web/prerequisites) (confirmed)
- A generic **class** is the shared template, a generic **object** one pass: ids are `<issuerId>.<suffix>`, alphanumerics, `.`, `_`, `-`. Object required fields: `id`, `classId`, `cardTitle`, `header`; also `subheader`, `textModulesData` (max 10), `barcode` {type QR_CODE, value, alternateText}, `linksModuleData` (max 10), `hexBackgroundColor`, `validTimeInterval`, `state` ACTIVE. [GenericObject](https://developers.google.com/wallet/reference/rest/v1/genericobject) (confirmed)
- Save link: `https://pay.google.com/gp/v/save/<jwt>`. The JWT is signed RS256 with the service account key; claims `iss` = service account email, `aud` = `google`, `typ` = `savetowallet`, `iat`, `origins` = [our origin], `payload` = {genericClasses?, genericObjects}. The class may travel inside the JWT. [JWT use case](https://developers.google.com/wallet/generic/use-cases/jwt) (confirmed). No size limit is on the page; we send one object and a class that holds only its id.
- Until the issuer is approved for production, only test users added in the console can save passes.
- **Location relevance today:** `merchantLocations` on the object or class, up to 10 each (it replaces the deprecated `locations`). Google decides the radius and dwell time and writes the notification text itself; entering a location gives a lock-screen notification (release notes 2025-10-14), tapping opens the pass. There is no relevantDate for a generic pass. The only time hooks are `validTimeInterval`, the 1-day-before "upcoming" and 2-days-before "expiry" notifications (`enableNotification`, only one applies). So: hotel coordinates go in `merchantLocations`; check-in time only in `validTimeInterval` (check-in to check-out). [Trigger push notifications](https://developers.google.com/wallet/generic/use-cases/trigger-push-notifications), [MerchantLocation](https://developers.google.com/wallet/reference/rest/v1/MerchantLocation), [release notes](https://developers.google.com/wallet/docs/release-notes). We set no notification flag (D-933).
- Badge: the [brand guidelines](https://developers.google.com/wallet/generic/resources/brand-guidelines) allow Google's own "Add to Google Wallet" button only (never our own version, 48 dp minimum, black). We use a text button for now (D-932).
